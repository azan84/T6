## 1. Machine and OS (reference, not a requirement)
AMD Ryzen Threadripper PRO 3955WX (16 cores / 32 threads, SMT on), 27 GB RAM visible to the guest, Windows host with **WSL2 Ubuntu 22.04.5 LTS** (kernel 6.6.87.2-microsoft-standard-WSL2), root disk 295 GB. `nproc` reports 32; **plan against 16 physical cores** (logical CPUs 2k and 2k+1 are the two threads of core k). A native Ubuntu 22.04 machine needs nothing else. The smoke test needs 8 cores and about 3 GB RAM.

## 4. Smoke test (about 5-6 minutes on 8 physical cores, reference run 318 s wall; the limit asked for is 30 minutes)
`smoke_test/` re-runs one returned case from scratch: the **Stage A sten70 vessel, A5 coarse mesh recipe (198,252 cells), steady laminar `simpleFoam`, coded resistance outlet (R = 6.974826e9 Pa s/m3, relax 0.2), 3000 iterations** (the original A5 run used 2000; a fresh run needs up to about 2750 to settle). The returned outlet flow is **1.17392231e-06 m3/s** (`returns/.../stageA_A5_ladders.csv`, A5 sten70 coarse).
```
cd code_from_cfd/smoke_test
./run_smoke_test.sh 8            # NPROC (default 8); WORKDIR (2nd argument) default ${TMPDIR:-/tmp}/paper6_t6_smoke_work (must not exist; a native Linux path outside this folder)
python3 test_compare_smoke.py    # optional: unit tests of the verdict logic (no OpenFOAM, seconds)
```
**Two branches (fix26, 2026-10-01).** At this resolution the case has two stable steady solutions on the same mesh recipe and cell count: a wall-deflected jet (outlet flow 1.17392231e-06 m3/s, FFR at x = 56.5 mm 0.78396 = the returned value) and an axisymmetric jet (1.17825059e-06 m3/s, FFR 0.78248; reference-machine smoke run 2026-10-01), 0.369 % apart. Which one a fresh run reaches is decided by micrometre-level differences of the cfMesh output and by the decomposition (cfMesh is not bitwise reproducible, so "same mesh" here means same recipe and cell count, not mesh identity); both states are stable for thousands of iterations. `reference_result.json` (schema 2) holds both branches with their provenance.
Steps: (1) `stageA/make_stageA_geometry.py --ds 70` writes `sten70.stl` (numpy only; sha256 must be `47178798e1052ddb7d23d8b318a934baaf42d93d5555b9568eddcabdf9ef8ef2`), (2) `cartesianMesh` (cfMesh, 4 boundary layers of ratio 1.2, maxCellSize 1.95e-4), (3) `checkMesh`, (4) `decomposePar` (scotch), (5) `mpirun -np NPROC simpleFoam -parallel`, (6) `compare_smoke.py` prints **SMOKE TEST PASS (<branch>)** iff the run finished all 3000 iterations, the mesh checks hold (STL hash, checkMesh OK, cell count equal to the reference) and the run sits on exactly one branch: outlet flow within **0.1 %** and FFR_x56.5 within **0.0005** of that branch, with a stable final window (last 200 iterations: flow band <= 0.01 %, FFR band <= 1e-5).
**What PASS means:** a correct install reaching one of the two validated states of this case. Only the deflected-jet branch ("SMOKE TEST PASS (deflected-jet branch = the returned A5 coarse value)") reproduces the returned value; a symmetric-jet PASS shows the same solver, mesher and set-up producing the other validated state. Report the branch, cell count, flow, FFR and wall clock. FAIL (exit 1) prints the distance to each branch; NON-COMPARABLE (exit 3) means the run is incomplete or the mesh checks failed.
**Reference governance (fix26).** Only the reference machine writes `reference_result.json`; a second machine only compares against the shipped file (both branches). `WRITE_REFERENCE=1 ./run_smoke_test.sh` adds the run as the branch it lands on and never touches the other branch entry; an existing entry is replaced only with `SMOKE_REPLACE_BRANCH=deflected` or `=symmetric` (forwarded as `--replace-branch`; a run landing on the other branch is refused, exit 2, file unchanged). Since the shipped file holds both branches, `WRITE_REFERENCE=1` without `SMOKE_REPLACE_BRANCH` stops in the preflight (exit 2) before anything expensive runs. By hand: `python3 compare_smoke.py <WORKDIR> reference_result.json --write-reference reference_result.json --replace-branch <branch>`. `compare_smoke.py` refuses (exit 2) a reference whose cells, STL hash, iteration count, returned value or branch values disagree with its built-in constants.
If the cell count of your mesh differs from the reference the comparison is not meaningful (cfMesh output can depend on the thread count: `export OMP_NUM_THREADS=8`, the reference run states the value used); report the cell count and the flow.
Failure hints: `wmake`/g++ missing -> the coded BC does not compile (install `openfoam2406-dev`, `build-essential`); `mpirun` refuses NPROC larger than the cores (pass a smaller NPROC); `cartesianMesh` writes the inlet and outlet patches with type `wall`, the script rewrites them to `patch`.

## 5. Rules that affect throughput on any machine
Total MPI ranks across concurrent jobs <= physical cores (16 here); bind ranks to cores (`mpirun --bind-to core --map-by core`; OpenMPI 4.1.2 ignores a `taskset` applied to `mpirun` and `--cpu-set` did not work on this host: the B2 runs pin each rank with a per-rank `taskset` wrapper, `task_0926/b2/b2_rank.sh`); the launcher `launch/run_set_generic.sh` refuses to start below 10 GB free on `/`; scan-14 real-lumen steady solves cost 2.1-2.3 h and about 6 GB per 3.5-3.9 M cells at 16 ranks for 3000 iterations (see `returns/2026-09-26/settle_iterations.csv` for the settle iterations: about 1000-1250 in resistance mode).
