It is contended and not a cost figure (its own log shows it: ClockTime 2050 s vs ExecutionTime 1241 s after 50 steps).

Case: the audited Item 6 sten60 pulsatile case (P/../item6_pulsatile_pilot/sten60_pulsatile: pimpleFoam, coded resistance BC, flowRateInletVelocity with the two-lobe table waveform of period 0.8 s, PIMPLE nOuterCorrectors 3, nCorrectors 2, adjustTimeStep on, maxCo 5, maxDeltaT 1e-3, scotch, 8 ranks). A FRESH COPY (task4/sten60_timing): old outputs removed (in each processor* directory every entry except 0 and constant, i.e. all time directories whatever their number format; removal only after checking that the copy path is <task4 root>/sten60_timing, a real directory), decompose.log kept (cell count), startFrom startTime 0 (the case's own 0/ fields), writeInterval 100 s (no field write in the timed steps); after N steps (default 300) the runner sets `stopAt noWriteNow` (v2406 Time.C: ends after the current step without writing).

Operation (task4_run.sh). The coordinator announces an exclusive interval (no Linux or Windows job may start until the run ends); the operator then runs `TASK4_EXCLUSIVE_OK=1 task4/task4_run.sh`. Refusals, each naming the offenders: u3d/queue4.log has no `queue4 finished` line; any solver/mesher/mpirun/orted or launcher/queue/heavy post-processing process (the runner and its ancestors excluded); 1-min load >= 1.5; < 10 GB disk; TASK4_EXCLUSIVE_OK unset; Windows-side load: powershell.exe, two Get-Process snapshots 10 s apart in ONE call, CPU-seconds delta per process, excluding vmmemWSL, vmmem, System, Idle and the querying powershell; refuse if one process > 0.25 core or the sum > 0.5 core (TASK4_ALLOW_WINDOWS_LOAD=1 logs the offenders and runs, contended=unknown); powershell.exe unavailable/failing: refuse unless TASK4_ALLOW_NO_WINDOWS_CHECK=1 (contended=unknown). Launch: `setsid mpirun -np 8 --bind-to core --map-by core --report-bindings pimpleFoam -parallel`; mpirun's PID is the session id of every rank = the owned group.
Watchdogs: TASK4_MAX_RUNTIME_S (5400 s from launch) and TASK4_NOPROGRESS_S (900 s without a new `Time =` line) both trigger the bounded stop and make the run INVALID. Bounded stop: SIGTERM to every member of the owned session, poll ALL survivors for 30 s, SIGKILL the survivors of that session only; the noWriteNow edit gets 120 s before the bounded stop. Every wait loop is bounded. An EXIT/INT/TERM trap stops the owned session (bounded stop), the memory logger and the isolation sampler, keeps the failure exit status and writes run_status.json (end_reason stop_honoured / endTime / watchdog_* / stop_ignored / interrupted_* / solver_exited_early, mpirun rc, bounded_stop none/SIGTERM/SIGKILL, controlled_end). Logger and sampler also exit by themselves when mpirun (or the runner) is gone. A SIGKILL of the runner itself cannot be trapped: run_status.json is written at launch with the session id (`kill -TERM -- -<sid>` by hand).
In-run evidence (task4_isolation.py sample, one python process, 5-s cadence like the logger): isolation_samples.csv = time, owned and NON-OWNED Linux CPU in cores from /proc/<pid>/stat deltas (utime+stime+reaped children's cutime+cstime, so short-lived jobs count; conservative) of all processes outside the owned session and the runner's own tree, top non-owned process, /proc/stat busy (cross-check only: this WSL2 kernel uses tick-sampled accounting and disagreed with per-process accounting in both directions in tests), non-owned CPU on the bound CPUs and their SMT siblings (attributed by each process's last CPU), steal, /proc/pressure/cpu total and fraction, MemAvailable, mean `cpu MHz` of the bound CPUs; every 60 s one Get-Process snapshot (about 1 s per powershell.exe call warm, 5 s cold; this costs a little Windows CPU itself, excluded as the querying process; its Linux-side interop process is owned) giving the Windows non-WSL CPU between snapshots. Rank affinities (Cpus_allowed_list of the pimpleFoam processes) go to rank_affinity.txt.
After the run: isolation_evidence.json = lscpu, NUMA nodes, the --report-bindings raw lines parsed (8 ranks on 8 distinct cores), observed rank affinities (8 disjoint sets on 8 distinct physical cores (package, core_id), each within one core) and their thread_siblings_list, governor ("unavailable in this WSL2 guest"; cpu MHz in WSL2 is the nominal value, turbo/power plan invisible; vCPU-to-physical placement is the hypervisor's and cannot be verified from the guest), pre- and post-run Windows per-process deltas, run statistics, and `contended`: "no" ONLY if the pre-run Windows check passed, non-owned Linux CPU mean < 0.25 and max < 1 core, Windows non-WSL CPU over the run < 0.5 core, no non-owned work on the bound CPUs/siblings (mean <= 0.1, max <= 0.5 core) and bindings verified (report AND observed affinity); "yes" if a threshold is exceeded; else "unknown".
Measurement (task4_analyse.py). OpenFOAM v2406 prints ExecutionTime = CPU time (user+system) of the master process and ClockTime = elapsed wall time in integer s. WALL s/step = (ClockTime[b] - ClockTime[a-1]) / (b-a+1) over the retained steps a..b (resolution 1/(b-a+1) s/step, reported); CPU s/step statistics (mean/median/p90/min/max, differences of consecutive ExecutionTime) as cpu_s_per_step_*, never as wall; a CPU/wall ratio near 1 is NOT evidence of no contention. Candidate window: steps skip+1 .. n-1 (exactly the first skip = 20 steps and the final stop step excluded; 0-based np.diff(ex)[skip-1:-1], clock[skip-1] .. clock[-2]). Retained = the longest contiguous run of candidate steps with printed max Co in [3.0, 5.05]; dt, Co, CPU and wall come from these same steps.
Courant window: the printed Co is computed from the previous step's flux with the previous deltaT, BEFORE setDeltaT adjusts dt (factor maxCo/Co, increase capped at 1.2 and by 1+0.1 f), so it is not the achieved Co of the newly solved step; a Co-limited run prints values scattered around 5. Measured in run_co5.log (controlled steps 12-50, n = 39): 4.924-5.011, 6/39 above 5.0, largest overshoot 0.0115. CO_HI = 5.05 (1 % above maxCo, about 4x that overshoot): a printed Co above 5.05 means the flux changed by more than 1 % in one step, i.e. not the steady Co-limited regime. The count and mean Co of the strict window [3.0, 5.0] are reported too.
Status: VALID only if run_status.json shows a controlled end (stop honoured or endTime, no bounded stop, rc 0) and the log has its End line, cells = 381,356, bindings verified, >= 200 retained steps of which at least half also lie in the strict window [3.0, 5.0] (co_mostly_above_5 otherwise; the count of retained strict steps is reported as steps_retained_strict_co_3_to_5 next to the candidate-window count), contended = "no" (read from isolation_evidence.json; missing = "unknown"). Both JSON files are type-checked: contended must be exactly the string "no", "yes" or "unknown" and bindings_verified the JSON boolean (otherwise evidence_malformed); controlled_end must be the JSON boolean true and mpirun_rc the integer 0 (a non-boolean controlled_end or a non-integer, non-null mpirun_rc gives run_status_malformed). Otherwise INVALID_<reasons>: all timing columns and projections are blank in the CSV; the console prints the numbers under an INVALID banner. No fallback.
Projection (wall-based, VALID only): flat = 0.8 s / mean dt of the retained steps x wall s/step / 3600 (the starting-flow dt held over the cycle). Flow-weighted = integral_0^0.8 Q(t)/Q_win dt / mean dt x wall s/step / 3600 (Q from constant/waveform.table, Q_win = mean Q over the retained steps; Q_start 1.3575e-6 m3/s vs cycle mean 1.5000e-6 m3/s, ratio 1.10497); it assumes dt proportional to 1/Q at fixed Co and is an ESTIMATE, not a validated full-cycle prediction (evolving velocity profiles and pressure iterations change the cost per step). A CPU-based projection appears only as cpu_projected_hours_per_cycle_CPU. The CSV `notes` and `co_window` columns carry these qualifications. Deliverable: returns/2026-09-24/item6_cost_isolated.csv (+ a row-wise note in NOTE.md that this replaces the contended estimate; the manuscript Item 6 subsection is updated).
Pre-run audit: agy + GPT-6 Astra (or the stand-in the study lead names) before the run; defects to Opus/Fable per the bug protocol.
Limits: 300 steps at the start of the cycle; the cost per step depends weakly on the solution state (GAMG iterations); memory-bandwidth effects of an idle vs busy host are exactly what "uncontended" removes; one mesh, one waveform.
Limits added in v1.2: Windows processes the non-admin user cannot open (about 120-130 here, e.g. services) report no CPU to Get-Process and are invisible (counted as null_cpu_processes); vmmemWSL itself is excluded, so Windows-side host contention reaching the VM only through the hypervisor is not measured (steal stays 0 in this guest); SMT-sibling occupancy is attributed by last CPU and is approximate.
