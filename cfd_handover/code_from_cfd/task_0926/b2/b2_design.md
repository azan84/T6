# Task B2 design (work order 2026-09-26): throughput layout, scan-14 baseline, resistance mode
Question: solves per hour of (i) ONE 16-rank job against (ii) TWO 8-rank jobs side by side on disjoint cores, each stopped at the B1 rule (settled proxy + flow bands < 0.1 % + BC error < 0.1 %).
Case: m1/cases/baseline_resistance (3,657,147 cells, coded resistance BC with the audited relax rule, laminar simpleFoam, the same dictionaries), copied to b2/L16/case, b2/L8/caseA, b2/L8/caseB (mesh + dynamicCode copied, decomposed with scotch),
controlDict endTime 1600 (B1 first-settled iteration of this case: 1229; margin 30 %; b2_prepare.sh writes 1400 and the coordinator edits the prepared cases to 1600 before the run; b2_run.sh refuses any other endTime), writeInterval 100000 (no field writes). Same physics/numerics in all layouts; only the decomposition and the core sets differ.
Layouts: L16 = mpirun -np 16 --bind-to none, every rank pinned by the wrapper b2_rank.sh to the two logical CPUs of ONE physical core (rank r -> cpus 2r, 2r+1: 16 physical cores, SMT siblings of a rank's core are its own second thread and idle). L8x2 = two jobs, each mpirun -np 8 --bind-to none with the same wrapper, job A on cores 0-7 (cpu base 0), job B on cores 8-15 (cpu base 16). Total ranks 16 in both (work order rule). Why a wrapper: OpenMPI 4.1.2 on this host ignores a taskset applied to mpirun (both jobs were re-bound to cores 0-7: found in a shim test, the observed Cpus_allowed_list of the ranks exposed it) and --cpu-set/--cpu-list fail silently; the SMT sibling mapping is cpu 2k/2k+1 = core k (sysfs).
Runner b2_run.sh (audited pieces of the Task 4 runner): refuses unless exclusive host (B2_EXCLUSIVE_OK=1), no simpleFoam/mpirun/mesher/queue process, load < 1.5, disk >= 10 GB, Windows side idle (powershell.exe per-process CPU, 0.25 core/process, 0.5 sum); umbrella b2_jobs.sh as session leader
(all solver processes in its session; bounded stop SIGTERM -> grace -> SIGKILL of the session only; max-runtime 4 h and no-progress 900 s watchdogs); sampler b2_isolation.py (Task 4 module generalised: simpleFoam, 16 ranks on 16 distinct physical cores) writes isolation_samples.csv and isolation_evidence.json (contended no/yes/unknown).
Measurement (b2_analyse.py): per job the B1 rule (b1_settle.analyse) gives the first-settled iteration; wall clock to it = ClockTime after that step (includes start-up) and the time-loop wall (minus ClockTime after step 1). Throughput: L16 = 3600/W; L8x2 = 3600/W_A + 3600/W_B (sum of the two rates, jobs run concurrently); 'paired' = 2 x 3600 / max(W_A, W_B).
Budget miss: a job that does not reach the B1 rule within its 1600 iterations is reported with settled=False and its last iteration; its layout's throughput is left empty with the note 'job X did not settle within N iterations' (the layout is not dropped silently) and the ratio is not computed.
Validity (strict): a layout is valid if it ended normally (controlled_end) and its isolation evidence says contended = 'no'. The pre-launch Windows guard (0.25 core per process, 0.5 sum; overrides B2_ALLOW_WINDOWS_LOAD=1 / B2_ALLOW_NO_WINDOWS_CHECK=1) and the strict `contended` of isolation_evidence.json are unchanged.
Conditional comparability on this WSL2 host (audit 0926 finding 3, relabelled by audit 0926-SETUPS finding 4): the PRIMARY validity is only the strict rule above (layout_status VALID, layout_valid True). The operator's Windows background (Windows Terminal, Chrome Remote Desktop remoting_host, about 0.25 core) trips the Windows guard; such a layout is labelled layout_status CONDITIONALLY_COMPARABLE (layout_valid False, valid_with_windows_background True), never VALID, when ALL hold:
(i) controlled_end; (ii) bindings_verified is true; (iii) sibling_of_bound_cpu_busy_with_nonowned_work is false (measured, no busy SMT sibling / bound CPU); (iv) every entry of contended_reasons is Windows-side ('Windows non-WSL CPU over the run over threshold', 'windows pre-run load...' incl. its override, 'windows pre-run check <status>'),
i.e. no non-owned Linux CPU over the thresholds, no missing Linux samples; (v) the Windows non-WSL CPU mean over the run is measured and < 1.0 core; (vi) the two layouts' Windows means differ by < 0.3 core (symmetry; not verifiable -> INVALID). No Linux-side or binding criterion is relaxed. Why not VALID: on WSL2 a similar mean Windows load does not prove equivalent temporal contention or Hyper-V core placement.
Ratio row, column ratio_status: 'VALID' (valid True) only if both layouts are VALID (note 'Windows background load W1/W2 cores, symmetric', W1 = L16, W2 = L8x2); 'CONDITIONALLY_COMPARABLE (sensitivity evidence only: Windows background load W1/W2 cores, symmetric; for a batch-layout decision stop the Windows-side background or run an order-reversed replicate)' (valid False) if both are at least conditionally comparable; otherwise 'NOT CLAIMED'. Known limits: WSL2 guest (Windows-side load only measured per process; vCPU-to-core placement by the hypervisor is not verifiable from the guest); one replicate per layout (an earlier uncontended solve of the same case with the same 16-rank layout gives a second L16 timing:
clock 4067 s at iteration 1229); the first ~100 iterations are slower (start-up transient), included consistently; thermal/turbo state not visible; the Chrome Remote Desktop process of the operator (about 0.25 core of Windows CPU) may be running and is then recorded in the evidence.
Order and host state (audit 0926-SETUPS finding 6): L16-then-L8x2 is a single replicate in one fixed order; page-cache, turbo and thermal state are not counterbalanced (no destructive cache clearing). b2_analyse.py writes run_order (1/2 by launch_epoch of run_status.json), launch_time and host_load_at_start (host_before.txt) on every job row. An earlier uncontended 16-rank solve of the same case exists (m1/cases/baseline_resistance/log.simpleFoam: clock 4067 s at iteration 1229) and serves as an independent L16 replicate. For a batch-layout decision an order-reversed replicate (L8x2 then L16) is recommended, with the ratio agreeing within a predeclared tolerance.
Metadata (audit 0926-SETUPS finding 5): b2_prepare.sh patches each copied build_info.json with b2_patch_buildinfo.py <case_dir> <nproc> (nproc = subdomains, endTime 1600, writeInterval 100000, b2_note; other keys kept; idempotent; refuses a file without these keys), so b1_settle reports ranks/budget of the prepared case; the already prepared L16/L8 cases are patched by the coordinator with the same script.
Paused foreign jobs (2026-10-01): the host's other project (OpenFOAM_Marissa: queue scripts, serial simpleFoam and mpirun jobs, ~50 processes) was paused with SIGSTOP on the operator's order (state T, RSS about 5.5 GB, no CPU; a watcher stops new ones). With B2_ALLOW_STOPPED_FOREIGN=1 the runner's offender guard ignores a process only if every one of its threads is stopped (T/t in /proc/<pid>/task/*/stat; unreadable -> not ignored) and it is not the runner's; any running offender still refuses. The ignored processes are listed in stopped_foreign_prerun.txt (count in host_before.txt). After the run stopped_foreign_postrun.txt records, per pre-run process, still stopped (same pid and start time, CPU time unchanged), resumed (CPU time grew or not stopped now), vanished (gone or pid reused) or undecided, and every foreign offender whose pid+start time is not in the pre-run list (a reused pid counts as new) as new_running or new_stopped. Resumed or new_running gives contended = yes ('foreign stopped job resumed during the run'); vanished or new_stopped gives contended = unknown unless already yes ('foreign stopped job vanished or new foreign job appeared during the run: CPU use not excluded': it may have run between two samples, which the sampler does not guarantee to see); undecided gives unknown. b2_analyse.py treats all of these as non-Windows reasons (INVALID). The sampler's per-PID non-owned CPU measurement is unchanged; a host-level measure is added (next paragraph). The result is therefore a throughput comparison on a host with about 5.5 GB held by paused foreign jobs, not an empty-host result. Memory is reported, not a validity criterion: per layout (isolation_evidence.json and every analysis row) the stopped foreign count and total RSS before and after the run, the minimum MemAvailable over the run (sampler), MemAvailable and swap used (SwapTotal - SwapFree) at start and end and whether swap grew, the host-wide pswpin/pswpout and pgmajfault deltas, the major page faults of the owned session (sampler, at each process's last sample) and the dmesg OOM lines during the run (or 'not readable'). The ratio row notes 'stopped foreign population differs between layouts' if the pid+start sets of the two layouts' pre-run stopped processes differ (the fixed run order would then add an asymmetry) and flags swap growth in either layout.
Host-level CPU and admission hardening (fix 27 attempt 3, audit SOL_FIX27_R2): (1) The per-PID non-owned measure only sees a process alive at two consecutive samples (or reaped by a non-owned process alive at both); a foreign job that starts and exits between two samples can escape it. The sampler therefore also writes host_cpu_samples.csv: at every sample it reads /proc/stat (aggregate and per-CPU busy = user+nice+system+irq+softirq+steal; guest is inside user; idle and iowait excluded; the 'processes' fork counter) and the owned processes' cumulative CPU utime+stime+cutime+cstime, keyed by pid+starttime (owned = the umbrella's session, the runner and its descendants, the sampler). Children reaped by an owned parent (also those born and gone between two samples) enter through the parent's cutime/cstime; an owned process that disappears has its previous total subtracted when its parent was owned (the parent's jump holds its final total), and nothing is subtracted if it was reaped outside the run (its later CPU then counts as non-owned: conservative). Non-owned host CPU per interval = max(0, host busy delta - owned delta). isolation_evidence.json gives its mean, p95 and max (run_host_nonowned_cores) and makes contended = yes ('host-level non-owned CPU over threshold') if mean >= HOST_MEAN_MAX or max >= HOST_MAX_MAX; no host samples -> unknown. Attempt 3 set HOST_MEAN_MAX = 0.30 / HOST_MAX_MAX = 1.25 core = the per-PID thresholds (0.25 / 1.0) plus a FIXED allowance of 0.05 / 0.25 core from a 60-s idle-host measurement (host-level minus per-PID non-owned 0.006 to 0.096 core per 5-s sample, mean about 0.045), because the two measures are not directly comparable: this WSL2 kernel accounts /proc/stat by tick sampling (CONFIG_TICK_CPU_ACCOUNTING, HZ 250) while per-process times are sum_exec_runtime based, and the host figure also holds irq/softirq, kernel threads and fork/exec cost that no process is charged for. That idle measurement did not bound the subtraction error under the 16-rank load (audit SOL_FIX27_R3 finding 2); the thresholds are therefore set by the calibration of the paragraph 'Host-level calibration' below. The per-PID measures are kept unchanged. The /proc/stat fork counter delta over the run and the owned and non-owned new pids seen at samples are recorded (host_forks) as information only; host_forks.nonowned_forks_upper_bound = forks minus the owned new pids seen is an UPPER BOUND on foreign forks (owned children that start and exit between two samples are never seen, and the runner, the sampler and the jobs fork such children), labelled so in the evidence and in the analysis column host_nonowned_forks_upper_bound; it is not a validity criterion. (2) Post-run exclusions of the runner, its ancestors, the sampler and the umbrella are by pid AND start time (recorded while alive: at the guard and at launch); session members are excluded only while the umbrella itself is alive with its launch start time, so a reused pid is never skipped. (3) Admission: one proc_info snapshot per candidate (thread states, start time, CPU, RSS read once): ignored only if that read succeeded and every thread is T/t; vanished, unreadable or any other state -> offender. The whole offender check runs again immediately before launch (after the Windows precheck and the OpenFOAM environment); a running offender or any change of the stopped pid:start set refuses (host_before.txt records the passed recheck). (4) Pause watcher (Fable attempt 1, audit SOL_FIX27_R3 blocker): the watcher must cover BOTH layouts (the earlier L16 solve alone took 4067 s to iteration 1229; the default of pause_marissa.sh --watch, 3600 s, is too short). Three forms exist: the original pause_marissa.sh --watch <s> (a full /proc scan every 10 s; started by the operator with --watch 36000 at about 06:00 on 2026-10-01 and ended), its replacement pause_marissa_light.sh <s> (started by the operator at 07:08:56 on 2026-10-01 with 43200 s; every 30 s two pgrep calls (solver/mesher/MPI executables and command lines naming the project or its queue/case/generator scripts), then ps/readlink on every match, SIGSTOP of any new running project process, appended to paused.pids; ended 07:55) and, since 07:55 on 2026-10-01, pause_marissa_light2.sh <s> (started with 43200 s, covering until about 19:55; pid in marissa_pause/watcher.pid; the same two pgrep calls every 30 s, but PIDs already seen stopped are skipped in memory, so the ~50 stopped PIDs are no longer inspected at every scan: the light form's per-scan ps/readlink calls cost up to 0.31 core in a 5-s sample of the calibration below). With B2_ALLOW_STOPPED_FOREIGN=1 the runner recognises all three forms (Fable attempt 2 added the light2 form; default <s> 36000 like the light form) (the script must be argv[0] or argv[1] of the process, so a shell whose command line merely mentions the name is not a watcher; a candidate of another form is listed as ignored), computes each live watcher's remaining coverage = <s> (the light form's argument, default 36000; the --watch argument, default 3600) minus the process's elapsed time (the watcher's end is its start + <s>), records pid, form, start time, elapsed, remaining and end time in host_before.txt, and REFUSES before the results directory exists ('pause watcher guard') and again at the pre-launch recheck (after the Windows precheck and the OpenFOAM environment) unless at least one recognised watcher is alive and the largest remaining coverage is at least B2_MAX_RUNTIME_S (default 14400 s per layout). There is no override for this refusal: without a watcher a foreign job started during the run would run unstopped. Any process the watcher stops during a layout makes that layout contended = unknown: an offender-pattern process is new_stopped at the post-run check, and in any case the watcher's log paused.pids (read only; its line count is recorded in host_before.txt at the guard and at the recheck) has new lines after the run (watcher_new > 0 in stopped_foreign_postrun.txt, reason 'pause watcher stopped new processes during the run'). The watcher is itself non-owned load measured by both non-owned criteria: the old form's 10-s scans forked about 500 processes and cost about 0.14 core (per-PID) and 0.28 core (host-level) in the samples that contained a scan; the light form's cost was measured by the calibration below: up to 0.312 core (per-PID) in a 5-s sample containing a scan, hence the operator's light2 form, whose cost is not calibrated separately (it does strictly less work per scan: two pgrep calls, no ps/readlink on already-seen PIDs) and is measured by the same criteria in every run.
Host-level calibration (Fable attempt 1, audit SOL_FIX27_R3 finding 2; b2_calibrate.sh, run ONCE before the measurement): a plain copy of b2/L16/case (the original is only read) under /home/azan/paper6_t6_work/b2_calib/<stamp>/L16/case with endTime set to a short budget (150 iterations) is run by the same b2_run.sh (calibration hook B2_CALIB_ENDTIME, accepted only for L16 under /b2_calib/, marked CALIBRATION in host_before.txt and run_status.json; all guards, the override and the watcher guard as in a measurement) through the same setsid b2_jobs.sh -> mpirun -np 16 --bind-to none b2_rank.sh launch (16 ranks pinned one per physical core) with the same sampler (5-s samples, Windows snapshot every 60 s), on the host as it is for the measurement (Marissa jobs stopped, light watcher alive, coordinator idle). The report calibration.json / calibration.txt gives host busy minus owned per sample (host_nonowned_cores, clamped at 0, and the raw difference): mean, p95 (nearest rank) and max over ALL samples (start-up and shutdown included, as in a measurement) and over the loaded samples (owned ledger >= 12 cores), the per-PID non-owned mean/max and the host-minus-per-PID difference. Threshold rule, stated before the run: with m, p95, M = mean, 95th percentile, max of host_nonowned_cores over all calibration samples, the subtraction is USABLE if m < 0.25 core (the error is below the per-PID mean threshold, so a foreign load of a quarter core on average is still distinguishable) and p95 < 1.0 core (fewer than 5 % of the samples reach the level of a 1-core foreign job); then HOST_MODE = criterion with HOST_MEAN_MAX = max(0.30, m + 0.25) and HOST_MAX_MAX = max(1.25, M + 1.0) core (rounded up to 0.01: the attempt-3 values are the floor, the calibration adds the per-PID thresholds to the measured noise). Otherwise the subtraction is UNUSABLE (its error is comparable to a 1-core foreign job): HOST_MODE = informational, the host-level figures are still recorded, and contended becomes 'unknown' (never 'yes') only above the gross thresholds HOST_GROSS_MEAN = 1.0 / HOST_GROSS_MAX = 4.0 core. The per-PID criteria (0.25 / 1.0) are not loosened in either case. Expected validity on this host (Fable attempt 2: what the calibration evidence implies for the real L16 and L8x2 runs; NO per-PID, sibling, host-level or Windows threshold is changed by this): (1) The strict sibling criterion (sibling_of_bound_cpu_busy_with_nonowned_work: the non-owned processes' CPU attributed to each process's last CPU, summed over the bound CPUs and their SMT siblings; busy if mean > SIB_MEAN_MAX 0.10 or max > SIB_MAX_MAX 0.5 core) counts, for L16, ANY non-owned work on ANY logical CPU, because L16 binds all 16 physical cores (cpus 0-31, the ranks' cores and their SMT siblings); for L8x2 the two jobs together bind the same 32 logical CPUs.
